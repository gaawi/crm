# Next.js 16 cheat sheet (App Router, Node runtime, Vercel)

Checked against the docs and `.d.ts` files bundled with `next@16.3.7` in `node_modules/next/dist/docs/`.
Lines tagged **[build]** were also confirmed with a throwaway `next build` / `next start` on 16.3.7.
Where the prose docs and the installed types disagree, the types win. Those cases are marked **Docs mismatch**.

## 1. `proxy.ts` (replaces `middleware.ts`)

- **Location:** `proxy.ts` goes in the project root, or in `src/` if you use one, at the same level as `app/`.
- **Export:** one function, either named `proxy` or the default export. A file can't export more than one.
- **Signature:** `(request: NextRequest, event: NextFetchEvent) => NextResponse | Response | null | undefined | void` (or a Promise of any of these). The `NextProxy` type from `next/server` infers both args. `ProxyConfig` types the `config` export.
- **Runtime:** always Node.js. Putting a `runtime` or other segment config in the proxy file throws: *"Route segment config is not allowed in Proxy file… Proxy always runs on Node.js runtime."*
- **`middleware.ts`:** still works, but is deprecated. **[build]** The build prints *"The "middleware" file convention is deprecated. Please use "proxy" instead."* Having both files is an error. Edge runtime is only possible via `middleware.ts`. `NextMiddleware` and `MiddlewareConfig` are `@deprecated` aliases. `skipMiddlewareUrlNormalize` is now `skipProxyUrlNormalize`. Codemod: `npx @next/codemod@canary middleware-to-proxy .`
- **Order:** next.config `headers` → next.config `redirects` → **proxy** → `beforeFiles` rewrites → filesystem routes → `afterFiles` → dynamic routes → `fallback`.
- **`config.matcher`:** accepts a string, an array of strings, or an array of `{ source, has?, missing?, locale?: false }`.
  - Syntax is path-to-regexp. Patterns must start with `/`. `:param` matches one segment, and `:path*`, `:path?`, `:path+` are the modifiers. `(regex)` groups are allowed.
  - Matches are anchored at the start: `/about` also matches `/about/team`.
  - Values must be constants because they are statically analysed. Variables are ignored.
  - With no matcher, proxy runs on **every** request, including `_next/static`, `_next/image` and `public/` assets.
- **Security:** Server Actions are POSTs to the page route. A matcher that excludes a path also skips the Server Actions on that path. The auth guide says to do only optimistic cookie checks in proxy (no DB) and to re-check auth in every action and route handler.

```ts
// proxy.ts   [build] compiles and runs as shown
import { NextResponse, type NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  const session = request.cookies.get('session')?.value // RequestCookies: get/getAll/has/set/delete/clear
  const { pathname } = request.nextUrl
  if (pathname.startsWith('/api/') && !session) {
    return Response.json({ error: 'unauthorized' }, { status: 401 }) // Response or NextResponse both OK
  }
  if (pathname.startsWith('/dashboard') && !session) {
    const url = new URL('/login', request.url)
    url.searchParams.set('from', pathname)
    return NextResponse.redirect(url)
  }
  return NextResponse.next() // pass modified request headers upstream with NextResponse.next({ request: { headers } })
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico|sitemap.xml|robots.txt).*)'],
}
```

**Docs mismatch:** `proxy.md` documents `unstable_doesProxyMatch` from `next/experimental/testing/server`. The installed 16.3.7 package only exports `unstable_doesMiddlewareMatch`, plus `isRewrite`, `getRewrittenUrl` and `getRedirectUrl`.

## 2. Route handlers (`app/api/**/route.ts`)

- **Methods:** `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD` and `OPTIONS`. Any other method gets a 405. If you don't export `OPTIONS`, it is implemented for you with the `Allow` header.
- **Arguments:**
  - The first arg is a `NextRequest`, which has `.nextUrl.searchParams` and `.cookies`.
  - The second arg is `context`, whose `params` is a **Promise**.
- **Placement:** `route.ts` and `page.tsx` can't live in the same segment.
- **`RouteContext<'/route'>`:** a global helper with no import needed. It is generated by `next dev`, `next build` or `next typegen`. Its shape is `interface RouteContext<R> { params: Promise<ParamMap[R]> }`.
- **Caching in v16 (without `cacheComponents`):** "Route Handlers are not cached by default." Only `GET` can opt in, via `export const dynamic = 'force-static'` or `revalidate`. Other methods are never cached. **[build]** Every GET handler was `ƒ (Dynamic)`, even one returning `Date.now()` without touching the request.
- **Also:**
  - `redirect()` and `notFound()` from `next/navigation` work in handlers.
  - Handlers take the same segment config as pages (see §4).

```ts
// app/api/contacts/[id]/route.ts
import { NextResponse, type NextRequest } from 'next/server'

export async function GET(_req: NextRequest, ctx: RouteContext<'/api/contacts/[id]'>) {
  const { id } = await ctx.params                       // or: { params }: { params: Promise<{ id: string }> }
  return Response.json({ id })
}

export async function POST(req: Request) {
  const body = await req.json()                         // also req.formData(), req.text()
  return NextResponse.json({ ok: true, body }, { status: 201 })
}

// Streaming: return a ReadableStream as the body
export async function PUT() {
  const enc = new TextEncoder()
  const stream = new ReadableStream({
    async start(controller) {
      for (const chunk of ['one\n', 'two\n']) controller.enqueue(enc.encode(chunk))
      controller.close()
    },
  })
  return new Response(stream, { headers: { 'Content-Type': 'text/plain; charset=utf-8' } })
}
```

## 3. `after()` (`next/server`)

- **Signature:** `after<T>(task: Promise<T> | (() => T | Promise<T>)): void`. It schedules work to run after the response (or prerender) finishes.
- **Where it works:** Server Components (including `generateMetadata`), Server Functions/Actions, Route Handlers and Proxy.
- **Always runs:** it still runs if the response failed, threw, or called `notFound()` or `redirect()`.
- **Request APIs inside the callback:**
  - In **Route Handlers and Server Actions**, you may call `cookies()` and `headers()` inside the callback.
  - In **Server Components**, calling them inside the callback throws. Read them before calling `after()` and close over the values.
- **Not a request-time API:** calling `after()` doesn't make a route dynamic. In a static page the callback runs at build or revalidate time.
- **Duration:** it runs for the route's platform-default or configured `maxDuration`, so raise `maxDuration` if the background work needs more time.
- **On serverless and Vercel:** "In Next.js and Vercel" it is implemented with `waitUntil(promise)`, which keeps the invocation alive until the promises settle. Other platforms have to supply `waitUntil` through `globalThis[Symbol.for('@next/request-context')]`. Proxy can also call `event.waitUntil(promise)` directly.

```ts
import { after } from 'next/server'
import { headers } from 'next/headers'
export async function POST(req: Request) {
  const data = await req.json()
  after(async () => { await audit((await headers()).get('user-agent'), data) }) // allowed in handlers/actions
  return Response.json({ ok: true })
}
```

## 4. Route segment config (`page` / `layout` / `route` exports)

| Export | v16, no `cacheComponents` | With `cacheComponents: true` |
|---|---|---|
| `runtime` | `'nodejs'` (default). `'edge'` is **deprecated** ("Remove the `runtime` export"). Not allowed in proxy. | Edge not supported. Node only. |
| `maxDuration` | `number` (seconds). Default comes from the platform. Set it on the **page** to change the timeout of all Server Actions on that page. | Same |
| `dynamic` | `'auto'` (default) \| `'force-dynamic'` \| `'error'` \| `'force-static'`. Still supported; documented in "Caching (Previous Model)". | **Removed**. Everything is dynamic by default. |
| `revalidate`, `fetchCache`, `dynamicParams` | Supported | **Removed** |
| `preferredRegion` | **Deprecated** | Deprecated |
| `experimental_ppr` | **Removed** in 16 (codemod available) | Use `cacheComponents` |
| `instant`, `prefetch` | No effect | Only work with `cacheComponents` |

Values must be statically analysable: `revalidate = 600` works, but `60 * 10` does not.

## 5. Pages and layouts

- **Promise props:** `params` (page and layout) and `searchParams` (page only) are **Promises**. v16 **removed** synchronous access. In Client Components, read them with React `use()`.
  - Layouts never receive `searchParams`.
  - Reading `searchParams` makes a page dynamic.
- **Global type helpers:** generated by `next dev`, `next build` or `next typegen`, with no import needed.
  - `PageProps<'/c/[id]'>` gives `{ params: Promise<…>; searchParams: Promise<Record<string, string | string[] | undefined>> }`.
  - `LayoutProps<'/c'>` gives `{ params: Promise<…>; children: React.ReactNode }` plus named parallel-route slots.
- **`notFound()`** (`next/navigation`, returns `never`):
  - It throws and renders the nearest `not-found.tsx`.
  - It also injects `<meta name="robots" content="noindex">`.
  - Call it in the render path: a component, or something the component awaits.
  - Allowed in Server Components, Server Functions and Route Handlers.
- **`redirect(url, type?)`** (`next/navigation`, returns `never`, so no `return` is needed):
  - Status codes:
    - 307 by default.
    - In a Server Action it does a client-side navigation, or a 303 for no-JS form posts.
    - `permanentRedirect()` gives 308.
  - The default history mode is `push` in Server Actions and `replace` elsewhere.
  - It throws, so call it **outside** `try/catch`.
- **Parallel routes:** every parallel-route slot now **requires** a `default.tsx`, or the build fails.

```tsx
// app/(app)/contacts/[id]/page.tsx
import { notFound } from 'next/navigation'
export default async function Page({ params, searchParams }: PageProps<'/contacts/[id]'>) {
  const { id } = await params
  const { tab = 'overview' } = await searchParams
  const contact = await getContact(id)
  if (!contact) notFound()
  return <h1>{contact.name} / {tab}</h1>
}
```

## 6. Server Actions

- **Defining actions:**
  - Put `'use server'` at the top of a file to mark every export as a Server Function; they must be async.
  - Or put `'use server'` at the top of an async function body inside a Server Component.
  - Client Components can't define actions. They import them from a `'use server'` file, or receive them as props.
- **Security and limits:**
  - Actions are **reachable by direct POST**, so authenticate, authorise and validate inside every action.
  - The client dispatches actions **one at a time**, so don't use `Promise.all` on them.
  - Default body limit is 1 MB (`experimental.serverActions.bodySizeLimit`).
- **Invoking:** `<form action={fn}>` or `<button formAction={fn}>`, where `fn` receives `FormData`. Extra args go in with `.bind`: `fn.bind(null, id)` gives `(id, formData)`.
- **`useActionState`** comes from **`'react'`** (types from `@types/react` 19.2):
  - `const [state, formAction, isPending] = useActionState(action, initialState, permalink?)`
  - The action's signature becomes `(prevState, formData)`.
- **`revalidatePath(path, type?: 'page' | 'layout')`** (`next/cache`):
  - `type` is required when `path` is a pattern such as `/c/[id]`.
  - In an action, it also refreshes previously visited pages on the next navigation.
- **`refresh()`** (`next/cache`): new in the v16 Caching APIs. It works **only in Server Actions** and throws in Route Handlers. It re-fetches the current route's RSC payload without invalidating cached data.
- **`updateTag(tag)`:** Server-Actions-only, read-your-writes. `revalidateTag(tag, profile)` now **requires** its 2nd argument (e.g. `'max'`).
- **Same-response re-render:** the action's response includes a fresh render of the current route only if the action calls `updateTag`, `revalidatePath` or `refresh`, sets or deletes a cookie, or calls `redirect`. Otherwise it carries **only the return value**. For a dynamic dashboard, call `refresh()` (or `revalidatePath`) after a mutation.
- **Redirecting after a mutation:** call `redirect()` after the revalidate call, because code after `redirect` never runs.

```ts
// app/(app)/contacts/actions.ts
'use server'
import { refresh, revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'
import { verifySession } from '@/lib/dal'
import { sql } from '@/lib/db'

export async function updateContact(id: string, prev: { error?: string }, formData: FormData) {
  const session = await verifySession()            // always re-check auth
  const name = String(formData.get('name') ?? '')
  if (!name) return { error: 'Name required' }
  await sql`update contacts set name = ${name} where id = ${id} and org_id = ${session.orgId}`
  refresh()                                       // or revalidatePath('/contacts/[id]', 'page')
  return {}
}
export async function deleteContact(id: string) {
  await verifySession(); /* delete */ revalidatePath('/contacts'); redirect('/contacts')
}
```
```tsx
'use client'
import { useActionState } from 'react'
import { updateContact } from './actions'
export function EditForm({ id }: { id: string }) {
  const [state, formAction, pending] = useActionState(updateContact.bind(null, id), {})
  return <form action={formAction}><input name="name" /><button disabled={pending}>Save</button>{state.error}</form>
}
```
The docs don't cover combining `.bind` with `useActionState`. The ordering above (bound args first, then `prevState`, then `FormData`) follows standard `Function.prototype.bind`.

## 7. `cookies()` / `headers()` (`next/headers`)

- **Types:** `cookies(): Promise<ReadonlyRequestCookies>` and `headers(): Promise<ReadonlyHeaders>`. Always `await` them.
  - **Docs mismatch:** some pages still say "you can still access it synchronously in Next.js 15". That is gone in 16; the types only return a Promise.
- **Cookie methods:** `get`, `getAll`, `has`, `set(name, value, options)` or `set({ name, value, ...options })`, `delete(name)` and `toString()`.
- **Where `set`/`delete` work:** only in **Server Functions and Route Handlers**, never during Server Component render, because headers are already streaming.
  - Setting a cookie in an action re-renders the current page.
- **Cookie options:**
  - `expires` (Date), `maxAge` (seconds), `domain`, `path` (the only default: `'/'`).
  - `secure`, `httpOnly`, `sameSite` (`boolean | 'lax' | 'strict' | 'none'`), `priority` (`'low' | 'medium' | 'high'`), `partitioned`.
- **Headers:** `headers()` is read-only. To set response headers, return them on a new `Response`.
- **Dynamic rendering:** calling either one in a page or layout makes the route dynamic.

```ts
import { cookies } from 'next/headers'
import { NextResponse } from 'next/server'
export async function POST() {                              // route handler; same API works in a Server Action
  const token = await createSession()
  const cookieStore = await cookies()
  cookieStore.set('session', token, { httpOnly: true, secure: true, sameSite: 'lax', path: '/', maxAge: 60 * 60 * 24 * 7 })
  return NextResponse.json({ ok: true })   // alternative: const res = NextResponse.json(...); res.cookies.set(...)
}
```

## 8. Caching defaults without `cacheComponents` (what we use)

Rule from the glossary: "Prerendering is the default for components that don't use Request-time APIs". Those APIs are `cookies()`, `headers()`, `searchParams` and `draftMode()`. `connection()` also stops prerendering. **A DB query is not a request-time API.**

**[build]** results on 16.3.7 (Turbopack and webpack gave the same output):

| Code | Build output |
|---|---|
| `page.tsx` that only `await`s an async DB-style query | **`○ Static`**: prerendered at build, so the query ran at build time |
| page that reads `cookies()` | `ƒ Dynamic` |
| page calling `await connection()` | `ƒ Dynamic` |
| layout with `export const dynamic = 'force-dynamic'`, plus the DB-only child page | `ƒ Dynamic` |
| layout calling `await connection()`, plus the DB-only child page | `ƒ Dynamic` |
| any `GET` route handler | `ƒ Dynamic` |

Things that do **not** help:
- In **dev**, pages are always rendered on demand, so a stale static page only shows up after `next build`.
- `fetch` is uncached by default, but that doesn't stop a page from being prerendered.
- `io()` from `next/cache` **resolves immediately when `cacheComponents` is off**, so it won't force dynamic rendering.
- `unstable_noStore` is legacy; use `connection()` instead.

**Recommended setup for the authenticated Postgres dashboard:**
1. Leave `cacheComponents` off.
2. Call `await connection()` at the top of the authenticated route-group layout, `app/(app)/layout.tsx`. Every page below it then renders at request time, even one that forgets to read cookies. The docs prefer `connection()` over `force-dynamic`; both work (**[build]**).
3. Do the real auth in a DAL. `verifySession()` wraps `cookies()` in `React.cache`; call it in every page, action and route handler. A layout auth check alone isn't enough, because layouts don't re-render on client navigation.
4. After a mutation, call `refresh()` or `revalidatePath()` inside the action (§6).
5. Wrap repeated queries in `React.cache` to dedupe them within one render.

```tsx
// app/(app)/layout.tsx
import { connection } from 'next/server'
export default async function AppLayout({ children }: { children: React.ReactNode }) {
  await connection()           // opt the whole authenticated area out of build-time prerendering
  return <>{children}</>
}
```

## 9. v16 breaking changes that matter for a new app

- **Minimum versions:**
  - Node **20.9.0+** (Node 18 dropped; `engines: ">=20.9.0"`).
  - TypeScript **5.1+**.
  - Browsers: Chrome/Edge/Firefox 111+, Safari 16.4+.
- **Turbopack is the default** for both `next dev` and `next build`.
  - Drop `--turbopack` from your scripts. Use `--webpack` to opt out.
  - A custom `webpack` config makes `next build` **fail** unless you pass `--webpack`.
  - Config moved from `experimental.turbopack` to top-level `turbopack`.
  - `~` Sass imports are unsupported.
- **`next lint` removed:** `next build` no longer lints, and the `eslint` key in next.config is gone. Run the ESLint CLI with **flat config** (`eslint.config.mjs` spreading `eslint-config-next/core-web-vitals` and `/typescript`, as this repo does).
- **Async request APIs only:** sync `cookies()`, `headers()`, `draftMode()`, `params` and `searchParams` are removed. The image and sitemap generator functions now get `params` and `id` as Promises.
- **`middleware` is now `proxy`,** and proxy is Node-only (§1). Edge runtime is deprecated for routes.
- **Caching APIs:**
  - `revalidateTag` needs a profile argument.
  - New `updateTag` and `refresh`.
  - `cacheLife` and `cacheTag` are stable, without the `unstable_` prefix.
  - PPR, `experimental.dynamicIO` and `experimental.useCache` are removed in favour of `cacheComponents`. Enabling it is *not* a rename; it changes the rendering model.
- **`next/image`:**
  - Local `src` with a query string needs `images.localPatterns[].search`.
  - `minimumCacheTTL` now defaults to 4 h (was 60 s).
  - `16` is gone from `imageSizes`.
  - `qualities` defaults to `[75]`; other values are coerced to the closest allowed one.
  - Local IPs are blocked unless `dangerouslyAllowLocalIP` is set.
  - `maximumRedirects` defaults to 3.
  - `images.domains` and `next/legacy/image` are deprecated; use `remotePatterns`.
- **Removed features:**
  - AMP.
  - `serverRuntimeConfig` and `publicRuntimeConfig`: use env vars, and `connection()` before reading `process.env` if the value must be read at runtime.
  - `devIndicators.appIsrStatus`, `buildActivity` and `buildActivityPosition`.
  - `unstable_rootParams`: use `next/root-params`.
- **Other changes:**
  - `next dev` writes to `.next/dev`, so dev and build can run concurrently; a lockfile prevents duplicate instances.
  - `size` and `First Load JS` are gone from the build output.
  - `process.argv.includes('dev')` is `false` in next.config under `next dev`.
  - Next no longer overrides `scroll-behavior: smooth`; add `data-scroll-behavior="smooth"` on `<html>` to restore the old behaviour.
  - React 19.2 (View Transitions, `useEffectEvent`, `<Activity>`).
  - `reactCompiler` is stable but off by default.
- **Codemods:**
  - `npx @next/codemod@canary upgrade latest`.
  - `next-async-request-api` is separate and not included in `upgrade`.

## 10. `serverExternalPackages`

- **Default:** Server Component and Route Handler dependencies are **bundled**. `serverExternalPackages: ['pkg']`, a stable top-level `NextConfig` key, opts a Node-specific dependency out so it loads with native `require`.
- **Built-in auto-external list** (from `dist/lib/server-external-packages.jsonc`): includes `pg`, `@prisma/client`, `prisma`, `better-sqlite3`, `mongodb`, `sharp`, `bcrypt`, `argon2`, `pino` and others. It does **not** include `postgres` (porsager).
- **Is it needed for `postgres`?** The docs don't say. **[build]** With `postgres@3`, Turbopack bundled it and needed no config. At runtime, both a route handler and a `connection()` page ran queries that failed only with `ECONNREFUSED` against a dummy host, meaning the driver itself worked. So it isn't required. Add `serverExternalPackages: ['postgres']` only if a bundling error ever appears.
- **Keep the DB module server-only:** add `import 'server-only'` to it.

```ts
// next.config.ts, only if needed
const nextConfig: NextConfig = { serverExternalPackages: ['postgres'] }
```

## 11. Vitest

Install `vitest`, `@vitejs/plugin-react`, `jsdom`, `@testing-library/react`, `@testing-library/dom` and `vite-tsconfig-paths` (the last one for the TS `@/*` paths).

```ts
// vitest.config.mts
import { defineConfig } from 'vitest/config'
import react from '@vitejs/plugin-react'
import tsconfigPaths from 'vite-tsconfig-paths'

export default defineConfig({
  plugins: [tsconfigPaths(), react()],
  test: { environment: 'jsdom' },
})
```
- **Script:** add `"test": "vitest"` to package.json. It runs in watch mode by default.
- **Limitation:** Vitest does **not support async Server Components**. Unit-test sync Server and Client Components, pure functions, actions' helpers and proxy logic. Cover async pages with E2E tests (Playwright).
- **Proxy tests:** use `next/experimental/testing/server`, which exports `unstable_doesMiddlewareMatch`, `isRewrite`, `getRewrittenUrl` and `getRedirectUrl` (see §1 mismatch).

## 12. Hook import paths

| Hook | Import | Signature |
|---|---|---|
| `useActionState` | `'react'` | `[state, dispatch, isPending] = useActionState(action, initialState, permalink?)` |
| `useFormStatus` | `'react-dom'` | `{ pending, data, method, action } = useFormStatus()`. Must be called in a component rendered **inside** the `<form>`. |
| `useOptimistic` | `'react'` | `[value, setOptimistic] = useOptimistic(passthrough, reducer?)` |
| `useTransition` / `startTransition` | `'react'` | Needed when you call an action from an event handler or `useEffect` |
